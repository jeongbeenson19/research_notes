### **Video Classification (2–3분 포맷)**

1. **Task 정의(1문장)**
    

  

- 비디오 전체(또는 긴 클립)를 입력으로 받아 전역 라벨(주제/장르/이벤트)을 예측한다.
    

  

2. **Output (10–15초)**
    

  

- single-label: K-way softmax 확률(Top-k 예측)
    
- multi-label: 각 클래스별 sigmoid 점수(태그 세트)
    

  

3. **Metrics (15–25초)**
    

  

- single-label: Top-1 / Top-5 accuracy
    
- multi-label: mAP
    
- 해석 포인트: 점수가 높아도 배경/장소 shortcut이면 실제 의미 이해와 괴리가 생길 수 있음.
    

  

4. **Protocol/Assumption (20–30초)**
    

  

- offline 가정이 일반적(전체 비디오 사용).
    
- 샘플링(몇 개 프레임/클립을 뽑는지)이 사실상 성능과 직결.
    
- split은 video-level이 보수적이며 clip-level 혼입은 과대평가 위험.
    

  

5. **난이도 2개 + 실패모드 1개 (≤60초)**
    

  

- 난이도1: long video noise — 관련 없는 구간이 많아 aggregation이 어려움.
    
- 난이도2: scene bias — 배경/오브젝트로 라벨을 찍는 편향.
    
- 실패모드: 짧게 등장한 핵심 이벤트를 놓치고, 비디오 전반 분위기/배경으로 오분류.
    

  

6. **방법론 계열(30–40초)**
    

  

- 2D 백본 + temporal aggregation(샘플링/풀링/late fusion)
    
- 3D conv/Transformer로 시공간 특징을 직접 학습(대신 compute·데이터 요구↑)
    
- 대규모 pretraining 후 finetuning이 성능을 좌우하는 경우가 많음.

### **Action Recognition (2–3분 포맷)**

1. **Task 정의(1문장)**
    

  

- 짧은 시간 구간(클립/세그먼트)을 입력으로 받아 그 구간의 행동 클래스를 분류한다.
    

  

2. **Output (10–15초)**
    

  

- clip-level K-way softmax 확률(Top-k)
    
- (세팅에 따라) 슬라이딩 윈도우로 여러 클립을 평가해 비디오 단위로 집계 가능
    

  

3. **Metrics (15–25초)**
    

  

- 기본: Top-1 / Top-5 accuracy
    
- 불균형이 크면: mean class accuracy(클래스별 정확도 평균)
    
- 해석 포인트: clip 길이/stride/windowing이 바뀌면 점수 자체가 달라져 “문제 설정” 영향이 큼.
    

  

4. **Protocol/Assumption (20–30초)**
    

  

- 핵심은 clip 정의(프레임 수/초 길이)와 sampling.
    
- online이면 짧은 컨텍스트 제약, offline이면 더 긴 문맥 활용 가능.
    
- 카메라 모션/촬영 조건 차이가 평가 결과에 직접 영향.
    

  

5. **난이도 2개 + 실패모드 1개 (≤60초)**
    

  

- 난이도1: motion vs appearance trade-off — 정지 단서로 되는 클래스와 모션이 필수인 클래스가 혼재.
    
- 난이도2: boundary ambiguity — 시작/끝이 애매해 라벨 노이즈가 구조적으로 존재.
    
- 실패모드: 배경 단서로 액션을 오인하거나, 카메라 패닝/줌으로 모션 특징이 붕괴해 오분류.
    

  

6. **방법론 계열(30–40초)**
    

  

- 2D + temporal module(가볍고 강한 기준선)
    
- 3D conv(모션 직접 학습, 비용↑)
    
- Transformer(긴 문맥·융합에 유리, 학습/추론 비용 이슈)
    
- pretraining 전략이 다운스트림 성능을 크게 좌우.

### **Object Tracking (2–3분 포맷)**

1. **Task 정의(1문장)**
    

  

- 비디오에서 관심 객체를 프레임마다 추적해 **위치(박스/마스크)와 연속성(같은 객체임을 유지)**을 유지한다. _(SOT: 단일 객체 / MOT: 다중 객체 + ID 유지)_
    

  

2. **Output (10–15초)**
    

  

- 공통: 프레임 t마다 객체의 **bbox(또는 mask) 시퀀스 = trajectory**
    
- SOT: 한 객체의 궤적(초기 박스/쿼리로 시작)
    
- MOT: 여러 객체의 궤적 + **ID(정체성) 부여**(예: ID=3의 bbox 시퀀스)
    

  

3. **Metrics (15–25초)**
    

  

- SOT:
    
    - **Success(AUC)**: IoU 기반 성공률 곡선의 면적
        
    - **Precision / Normalized Precision**: 중심점 오차 기반
        
    - (VOT 계열) **EAO**: 정확도+강건성(실패/리셋 포함)
        
    
- MOT:
    
    - **HOTA**: detection+association 균형(요즘 설명용으로 깔끔)
        
    - **IDF1**: ID 유지 품질(정체성 보존)
        
    - **MOTA**: FN/FP/IDSW 종합(해석 주의), **IDSW**, **Frag** 같이 함께 언급
        
    
- 해석 포인트: MOT는 “잘 찾았냐(Detection)”와 “같은 애로 유지했냐(Association)”가 분리되므로 **IDF1/HOTA를 같이** 보는 게 안전함.
    

  

4. **Protocol/Assumption (20–30초)**
    

  

- **Online vs Offline**: 과거 프레임만 쓰는지(online) / 미래까지 보는지(offline)
    
- **Initialization**: SOT는 보통 첫 프레임 GT 박스 제공, 이후 추적
    
- **Detections 제공 여부(MOT)**:
    
    - tracking-by-detection(검출 결과로 association) vs end-to-end(검출+추적 통합)
        
    - public/private detections(평가 세팅에 따라 성능 비교가 달라짐)
        
    
- 프레임레이트/해상도, 카메라 모션 유무가 난이도에 직접 영향
    

  

5. **난이도 2개 + 실패모드 1개 (≤60초)**
    

  

- 난이도1: **Occlusion/Out-of-view** — 가려지거나 화면 밖으로 나갔다가 재등장
    
- 난이도2: **Appearance 변화** — 포즈/스케일/조명/모션블러/배경 혼합으로 외형이 계속 바뀜
    
- (MOT 추가 난이도) **유사 객체 다수** — 서로 비슷하게 생긴 객체가 근접 이동
    
- 실패모드:
    
    - SOT: **drift**(배경/다른 객체로 추적이 미끄러짐)
        
    - MOT: **ID switch**(ID가 바뀜) 또는 **fragmentation**(궤적이 끊김)
        
    

  

6. **방법론 계열(30–40초)**
    

  

- SOT:
    
    - **Correlation filter**(고전) → **Siamese 기반**(template–search 매칭) → **Transformer tracker**(전역 상호작용/강한 백본)
        
    
- MOT:
    
    - **Tracking-by-detection + association**(가장 흔함): detector + (Kalman/Hungarian) + appearance(ReID)
        
    - **강한 association 중심**(DeepSORT류) / **검출 강함 중심**(ByteTrack류) / **occlusion 강화**(OC-SORT류)
        
    - **End-to-end**(TrackFormer/DETR계열 등): 검출과 추적을 통합해 학습
        
    
- 코멘트 1줄: MOT는 많은 경우 **detector 품질이 상한을 결정**하고, 그 위에서 association이 IDF1/HOTA를 갈라놓는다.

### **Re-Identification (2–3분 포맷)**

1. **Task 정의(1문장)**
    

  

- 서로 다른 시간/카메라/시점에서 관측된 객체(사람/차량 등)가 **동일 ID인지**를 판별하기 위해, query에 대해 gallery에서 같은 ID를 **검색(retrieval)**하는 문제다.
    

  

2. **Output (10–15초)**
    

  

- 기본 출력은 **임베딩 벡터(embedding)**: 이미지/트랙릿 → d차원 특징
    
- 추론 시에는 **query–gallery 유사도 점수**를 계산해 **랭킹 리스트(top-k)**를 반환
    
    - (분류가 아니라) “가장 비슷한 후보를 순서대로 나열”이 핵심
        
    

  

3. **Metrics (15–25초)**
    

  

- **CMC / Rank-k (R1, R5, R10)**: 정답이 상위 k 안에 있으면 성공
    
- **mAP**: query별 precision-recall을 랭킹 전체에서 평가(다중 정답/다중 매칭에 강함)
    
- (자주 같이 나오는 보조) **mINP**: “정답이 랭킹에서 얼마나 뒤로 밀렸는지”를 더 민감하게 반영
    
- 해석 포인트: **R1은 ‘첫 후보가 맞냐’**, **mAP는 ‘전체 랭킹 품질’**이라 둘이 서로 다르게 움직일 수 있음.
    

  

4. **Protocol/Assumption (20–30초)**
    

  

- **Query/Gallery 구성**: 한 query에 대해 같은 ID가 gallery에 여러 장 있을 수 있음(현실적)
    
- **Single-camera vs Cross-camera**: 같은 카메라 내 재등장 vs 카메라 간 재등장(난이도 차 큼)
    
- **Image ReID vs Video ReID**: 단일 이미지 vs 트랙릿(여러 프레임)
    
- **Open-set 성격**: gallery에 “정답이 아예 없는” 상황(unknown)까지 다루는지 여부가 별도 과제(일반 ReID 벤치마크는 보통 closed-world 가정)
    

  

5. **난이도 2개 + 실패모드 1개 (≤60초)**
    

  

- 난이도1: **Viewpoint/pose/scale 변화** — 같은 대상이라도 실루엣이 크게 바뀜
    
- 난이도2: **조명/카메라 스타일(domain shift)** — 센서/화이트밸런스/압축으로 외형 분포가 달라짐
    
- (추가 후보) **occlusion + background clutter**, **유사 복장/유사 외형(동질 객체 밀집)**
    
- 실패모드: “배경/장소/동반 객체 같은 **context shortcut**에 과의존해서, 다른 ID를 같은 ID로 끌어오는 오매칭”
    

  

6. **방법론 계열(30–40초)**
    

  

- **Metric learning 파이프라인(표준)**: backbone(CNN/ViT)로 임베딩 → 거리(코사인/유클리드)로 검색
    
- 학습 손실 축:
    
    - **ID 분류(softmax 계열)**로 클래스 분리 + **pair/triplet 계열**로 거리 구조 정렬
        
    
- 표현 강화 축:
    
    - **part-based/attribute-aware**(신체 부위/지역 특징)
        
    - **attention/Transformer**(가림·시점 변화에 강한 특징 선택)
        
    
- Video ReID의 경우:
    
    - 프레임 임베딩을 **temporal aggregation**(평균/어텐션/시퀀스 모델)해 트랙릿 표현을 만든다.

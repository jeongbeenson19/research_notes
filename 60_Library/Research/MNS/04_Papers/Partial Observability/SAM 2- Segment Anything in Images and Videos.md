## **📄 SAM 2: Segment Anything in Images and Videos 개요**

- **발표 논문**: SAM 2: Segment Anything in Images and Videos (Nikhila Ravi et al., ICLR 2025)[1][2][3][4][5]
- **핵심 아이디어**:
    [[SAM 2]]는 이미지와 비디오 모두에서 프롬프트 기반 시각적 분할(promptable visual segmentation)을 해결하기 위한 [[파운데이션 모델]](foundation model)이다[2][6]. 기존 [[Segment Anything Model (SAM)]]이 이미지에만 초점을 맞춘 것과 달리, SAM 2는 단일 통합 아키텍처로 이미지와 비디오 분할 기능을 결합한다[7][8][9]. 실시간 비디오 처리를 위해 스트리밍 메모리(streaming memory)를 갖춘 간단한 [[트랜스포머]](transformer) 아키텍처를 활용하며[2][10][6], 사용자 상호작용을 통해 가장 큰 비디오 분할 데이터셋인 SA-V를 구축했다[2][8][6]. 사용자는 클릭, 박스, 마스크와 같은 프롬프트를 통해 객체를 대화식으로 분할할 수 있으며, 모델은 프레임 간 객체 연속성을 유지하는 메모리 메커니즘을 사용한다[1][7].
- **주요 성과**:
    - 비디오 분할에서 기존 방법론 대비 3배 적은 상호작용으로 더 나은 정확도를 달성했다[2][6].
    - 이미지 분할에서 기존 SAM보다 더 정확하고 6배 더 빠르다[2][10][6].
    - Hiera-B+ 모델 기준으로 약 44 FPS의 실시간 처리 속도를 제공한다[7][10].
    - 광범위한 작업에서 강력한 성능과 [[제로샷 일반화]](zero-shot generalization) 능력을 보여준다[2][7][6].
    - 23개 데이터셋에서 SAM 대비 더 높은 정확도(1클릭 시 58.9 mIoU vs 58.1 mIoU)를 달성했다[10].

## **🏗 아키텍처 개요**

[[SAM 2]]는 [[SAM]]의 비디오(및 이미지) 도메인으로의 일반화된 형태이다[1][10].

### **0. 기호/차원**
- $I_t$: 시점 $t$의 입력 이미지 또는 비디오 프레임
- $P_t$: 시점 $t$의 사용자 프롬프트 (점, 박스, 마스크)
- $M_t$: 시점 $t$의 출력 분할 마스크
- $E_{img}$: 이미지 임베딩
- $E_{mem}$: 메모리 임베딩 (과거 예측 및 프롬프트된 프레임 정보 포함)

### **1. 이미지 인코더 (Image Encoder)**
- **구성**: 계층적 이미지 인코더 (Hierarchical Image Encoder, Hiera)[10]
- **특이 사항**: 고해상도 정보 추출을 위해 스킵 연결(skip connections)을 활용한다[10].

### **2. 마스크 디코더 (Mask Decoder)**
- **구성**: 프롬프트 가능한 경량 마스크 디코더 (promptable and light-weight mask decoder)[1][10]
- **각 층**:
    1. **[[프레임 임베딩]](Frame Embedding)**: 이미지 인코더의 출력과 과거 예측 및 프롬프트된 프레임의 메모리 정보($E_{mem}$)를 조건으로 생성된다[1].
    2. **[[프롬프트 처리]](Prompt Processing)**: 현재 프레임에 대한 사용자 프롬프트($P_t$)를 입력으로 받아 처리한다[1][10].
- **특이 사항**: 모호한 프롬프트(예: 단일 클릭)에 대해 여러 개의 마스크를 예측하여 유효한 출력을 보장한다[10].

### **3. 메모리 메커니즘 (Memory Mechanism)**
- **구성**: 스트리밍 메모리 (streaming memory)[2][10][6] 및 메모리 인코더 (memory encoder)[8]
- **특이 사항**:
    - 객체의 시간적 연속성을 추적하고 유지한다[7][8].
    - 과거 예측 및 프롬프트된 프레임의 정보를 저장하고 활용하여 현재 프레임의 분할에 영향을 미친다[1].
    - 객체가 사라질 가능성을 설명하기 위한 [[가려짐 예측 헤드]](occlusion prediction head)를 포함한다[10].

## **🎯 주요 구성 요소**

### **1. [[스트리밍 메모리]](Streaming Memory)**
- 입력/출력 및 작동 원리 설명: [[SAM 2]]의 핵심으로, 실시간 비디오 처리를 가능하게 하며 프레임 간 객체의 연속성을 유지하는 데 사용된다[2][7][10][6]. 과거 프레임의 예측 및 프롬프트 정보를 저장하고 이를 현재 프레임의 분할에 활용한다[1].
- $$E_{mem} = \text{MemoryEncoder}(\text{PastPredictions}, \text{PromptedFrames})$$

### **2. [[프롬프트 기반 분할]](Promptable Segmentation)**
- 병렬 처리, 분할, 혹은 특수 기능 설명: 점, 박스, 마스크 등 다양한 형태의 사용자 프롬프트를 입력으로 받아 객체를 분할한다[1][10]. 사용자가 실시간으로 상호작용하여 분할 결과를 정제할 수 있다[1].
- 설정 값 (논문 기준): 프롬프트는 단일 프레임 또는 여러 프레임에 걸쳐 제공될 수 있다[1].

### **3. [[가려짐 예측 헤드]](Occlusion Prediction Head)**
- 객체가 현재 프레임에서 가려지거나 사라질 가능성을 예측하는 MLP 헤드(MLP head)이다[10]. 이를 통해 유효한 객체가 존재하지 않는 프레임에 대한 처리를 개선한다[10].

## **⚖️ [SAM 2] vs [SAM]**

| **비교 항목** | **[SAM 2]** | **[SAM]** |
| :--- | :--- | :--- |
| **분할 기능** | 이미지 및 비디오[7][8][9] | 이미지 전용[8][9] |
| **속도 (이미지)** | 6배 빠름[2][10][6] | - |
| **정확도 (이미지)** | 더 정확함 (1클릭 시 58.9 mIoU)[10] | 1클릭 시 58.1 mIoU[10] |
| **비디오 처리** | 스트리밍 메모리 기반, 실시간 (44 FPS)[2][7][10][6] | 비디오 분석에 비효율적, 메모리 부족[9] |
| **상호작용 (비디오)** | 3배 적은 상호작용[2][6] | - |
| **복잡도** | $O(\dots)$ | $O(\dots)$ |

- [[SAM 2]]는 [[SAM]]의 한계였던 비디오 처리 능력과 실시간 성능을 크게 개선하여, 이미지와 비디오 모두에서 강력한 [[파운데이션 모델]]로서의 역할을 수행한다[7][8][9]. 특히, 스트리밍 메모리 메커니즘을 통해 시간적 연속성을 유지하며 효율적인 비디오 분할을 가능하게 한다[7][8].

---

## **🧠 [추론/디코딩/생성] 과정**
- **방식**: 프롬프트 기반 (Prompt-based)[1][10]
- **특징**:
    - 사용자 프롬프트(점, 박스, 마스크)를 입력으로 받아 현재 프레임의 분할 마스크를 생성한다[1][10].
    - 프레임 임베딩은 과거 예측 및 프롬프트된 프레임의 메모리 정보를 활용하여 조건화된다[1].
    - 모호한 프롬프트의 경우 여러 마스크를 예측하며, 추가 프롬프트로 모호성을 해결하지 못하면 가장 높은 IoU를 가진 마스크를 선택하여 전파한다[10].
    - 객체가 가려질 경우를 대비하여 가려짐 예측 헤드를 통해 객체 가시성 점수를 제공한다[10].

## **⚠️ 한계**
- 얇은 구조물, 빠르게 움직이는 객체, 유사한 객체들이 밀집된 혼잡한 장면에서 분할 성능이 저하될 수 있다[11][8].
- 여러 객체를 처리할 때 각 객체를 독립적으로 처리하므로, 객체 트랙 간의 통신이 없어 다중 객체 처리 능력이 제한적이다[11][8].
- 메모리 메커니즘이 최근 프레임과 프롬프트된 프레임만을 공간 특징 맵(spatial feature maps)으로 저장하여, 가려짐이나 외형 변화를 통한 추적에 중요한 시간적 패턴을 놓칠 수 있다[11].
- 높은 메모리 소비: 5초 분량의 비디오 처리에 약 12GB의 RAM이 필요할 수 있다[12].
- 3D CT 이미지 분할과 같은 특정 도메인에 [[제로샷]](zero-shot) 방식으로 직접 적용할 경우, 객체가 사라질 때 오탐(false positives)을 생성하기 쉽고 만족스럽지 못한 결과를 보일 수 있다[13].
